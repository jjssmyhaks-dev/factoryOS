# ADR-001: Repo structure

- **Status**: accepted
- **Date**: 2026-09-21
- **Deciders**: founder (SRB), PRD §4.4
- **Context**: One team (founder + autonomous agents) must ship a five-layer product across web, workers, workflows and a Windows bridge without dependency hell or duplicated tooling.
- **Decision**: **pnpm workspaces + Turborepo monorepo** with `apps/`, `services/`, `packages/`, `infra/`, `docs/` layout exactly as in PRD §4.4.
- **Alternatives considered**: multi-repo per service (rejected: cross-package refactors become multi-PR coordination); npm/yarn workspaces (rejected: slower, weaker linking).
- **Consequences**: single CI pipeline, shared tsconfig/eslint, one version bump per package; requires discipline about package boundaries (`packages/domain` stays pure).
- **Verification**: `pnpm install && pnpm ci` passes on a clean clone (E0-S1).
