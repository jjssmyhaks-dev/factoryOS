# ADR-014: Device connectivity — AWS IoT Core

- **Status**: accepted
- **Date**: 2026-09-21
- **Deciders**: founder (SRB), PRD §4.4
- **Context**: Tally Bridge (Phase 1) and edge gateways (Phase 3) need outbound-only, mutually authenticated, bidirectional channels with per-device revocation — without opening inbound ports at customer sites.
- **Decision**: **AWS IoT Core** (MQTT over TLS, per-device certificates, IoT Rules → SQS, IoT Jobs for OTA). WebSocket-on-443 and HTTPS long-poll fallbacks for restrictive networks; bulk data via presigned S3 URLs (§4.3).
- **Alternatives considered**: plain WebSocket server (rejected: needs inbound endpoint + auth plumbing); polling HTTPS only (rejected: latency for control messages).
- **Consequences**: device certificate revocation = our kill switch (<60 s, E4-S1); IoT message size limits mean control messages carry references only **[VERIFY exact limits]**.
- **Verification**: pairing + revocation test (E4-S1); fallback transport test.
