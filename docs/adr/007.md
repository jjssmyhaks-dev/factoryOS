# ADR-007: LLM data residency and redaction — OPEN, founder decision required

- **Status**: proposed — **blocking first design partner** (PRD §15.3 item 1)
- **Date**: 2026-09-21
- **Deciders**: founder (SRB)
- **Context**: Competitors advertise "data never leaves Indian servers." Model inference geography is unsettled: providers may not offer India regions. NFR-5 requires customer data in `ap-south-1` with exceptions documented.
- **Decision needed**: choose one before the first design partner signs:
  1. Use a provider region in India, if available for the chosen model.
  2. Redact/tokenize personal and financial identifiers (phone, GSTIN, PAN, bank details) **before** external inference, rehydrate after (reuses the §7.2 redaction layer).
  3. Accept the exception and disclose it in the privacy policy.
- **Interim default (M0)**: option 2 architecture — the redaction layer exists in `packages/observability` regardless; M0 uses a mock model provider so foundations do not block on this.
- **Consequences**: E15-S4 implements whichever option is chosen; provider contract terms recorded.
- **Verification**: record the founder's choice here before onboarding partner #1.
