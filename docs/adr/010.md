# ADR-010: Semantic layer — in-house YAML metric catalog

- **Status**: accepted
- **Date**: 2026-09-21
- **Deciders**: founder (SRB), PRD §4.4
- **Context**: The owner brief and data agent need governed metrics (E10) over our Postgres schema; Cube/dbt add always-on services or heavy Python runtimes.
- **Decision**: **In-house YAML metric catalog + query planner in `packages/semantic`**; LLM outputs a structured plan validated against the catalog, never raw SQL (E10-S2). Revisit Cube or dbt semantic layer at scale.
- **Alternatives considered**: Cube (always-on API + Redis unless serverless tier); dbt semantic layer (Python + fivetran API coupling).
- **Consequences**: we own permission enforcement in the executor; catalog needs tests against seeded data.
- **Verification**: ≥25 metrics with tests (E10-S1); permission matrix enforced (E1-S4).
