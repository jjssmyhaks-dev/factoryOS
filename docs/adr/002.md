# ADR-002: Orchestration — Step Functions Standard workflows

- **Status**: accepted
- **Date**: 2026-09-21
- **Deciders**: founder (SRB), PRD §4.4
- **Context**: Agent runs and the action lifecycle (§6.3) need durable waits for human approval (24 h), retries, and visible execution history — inside a serverless-only policy (§4.2).
- **Decision**: **Step Functions Standard workflows** for agent runs and the action lifecycle. The transition table lives in `packages/harness`; the workflow definition is generated from it (`scripts/generate-workflows.ts`) and CI fails on divergence (`scripts/check-workflow-transitions.ts`). LangGraph only inside a single Lambda step if needed.
- **Alternatives considered**: BullMQ + Redis (rejected: always-on, violates §4.2); Express workflows (rejected: no 1-year execution history, no waitForTaskToken durability); Temporal (rejected: always-on server).
- **Consequences**: workflows must stay coarse (cost per state transition, §4.3); execution ID = run_id/action_id for traceability.
- **Verification**: property tests on the transition table; Step Functions TestState spike **[VERIFY]**.
