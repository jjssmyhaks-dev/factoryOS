# ADR-003: Multi-tenancy — shared schema with tenant_id + RLS

- **Status**: accepted
- **Date**: 2026-09-21
- **Deciders**: founder (SRB), PRD §4.4
- **Context**: Many small MSME tenants, solo team; isolation must be absolute (principle 7) without per-tenant operational overhead.
- **Decision**: **Shared schema, `tenant_id` column on every tenant-scoped table, Postgres RLS** using transaction-local `set_config('app.tenant_id', …, true)` (§4.5). Per-tenant database remains an enterprise option (E44).
- **Alternatives considered**: per-tenant DB (rejected: migration and cost overhead at 100+ tenants); application-layer `WHERE tenant_id =` only (rejected: one missing filter = cross-tenant leak).
- **Consequences**: every new table ships with a policy and an isolation test (CI-enforced); pooling must stay transaction-mode.
- **Verification**: RLS enumeration + cross-tenant denial tests in CI (E1-S3).
