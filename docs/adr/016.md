# ADR-016: Inbound email — SES inbound if available, else third-party webhook

- **Status**: proposed (default in use: SES-with-fallback design)
- **Date**: 2026-09-21
- **Deciders**: founder (SRB), PRD §4.4 / Q11
- **Context**: Per-tenant inbound addresses turn emailed supplier invoices into `documents` (E5-S5). SES receiving rules + S3 event exist in some regions but not all features everywhere.
- **Decision**: **SES inbound if available in the region [VERIFY]**; otherwise a third-party inbound webhook provider. The ingress Lambda contract (verify → persist raw → enqueue → 2xx) is identical either way.
- **Alternatives considered**: running our own MX/IMAP poller (rejected: always-on or polling cost + deliverability).
- **Consequences**: SPF/DKIM results recorded per message; failures quarantined (E5-S5).
- **Verification**: region feature check before E5; spike notes go in `docs/spikes/`.
