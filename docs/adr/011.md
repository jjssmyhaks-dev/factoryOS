# ADR-011: Database platform — Supabase Postgres (Mumbai)

- **Status**: accepted (founder confirmation requested in PRD §15.3 item 5)
- **Date**: 2026-09-21
- **Deciders**: founder (SRB), PRD §4.4
- **Context**: We need Postgres + RLS + pgvector + auth + transaction-mode pooling in one managed service; Aurora Serverless v2 is "purer" serverless but needs RDS Proxy, Secrets Manager wiring and custom auth.
- **Decision**: **Supabase Postgres (Mumbai region) with the transaction pooler; Drizzle ORM for typed queries and hand-written SQL migrations for RLS and policies.** Honest exception: compute is always-on (§4.2).
- **Alternatives considered**: Aurora Serverless v2 + RDS Proxy (closer to pure serverless; more AWS wiring; revisit if an enterprise customer requires private networking — Lambdas have no static egress IP, so protection rests on TLS, per-role credentials and RLS).
- **Consequences**: `set_config(..., true)` transaction-local tenant context is mandatory (no session `SET`); pooler behavior with `set_config` must be **[VERIFY]**-tested.
- **Verification**: [VERIFY] pooler + RLS behavior; Testcontainers run the same policies locally.
